**The Failure Mode:**
If the server returns a valid HTTP 200 but with an error payload (e.g., `{"choices": [], "error": {"message": "Model overloaded"}}`), this line executes `[] or [{}]` -> `[{}]`. It then attempts `[0]`.
*   **Result:** `IndexError: list index out of range`.
*   **Impact:** This exception is *not* caught by the `httpx.HTTPStatusError` handler (which only catches HTTP codes >= 400). It bubbles up to the generic `except Exception` block.

**Corrective Change:**
Check for `obj.get("error")` before parsing `choices`. If `choices` is empty, return the server's error message.

**Code:** `if "content" in delta and delta["content"]: chunks.append(delta["content"])`

*   **Impact:** The CLI reports "Success" with 0 tokens and 0 seconds of wall time (if the server returned immediately). The user gets a blank review. This is a silent data loss.

**Corrective Change:**
Validate that `chunks` is non-empty or that `finish_reason` is `stop` *and* content exists. If `finish_reason` is `stop` but content is empty, treat it as an error.

#### Finding 3: Blocking I/O in Async Context
**Location:** `main_async`, lines ~165-166
**Code:** `diff = diff_path.read_text()` and `load_lens_prompt` (which calls `path.read_text()`)

*   **Impact:** While not a "race" in the traditional sense, it delays the start of all concurrent requests. In a high-throughput scenario, this adds latency to every request.

**Corrective Change:**
Move file reading to the synchronous `main()` function, or use `asyncio.to_thread` to offload I/O.
